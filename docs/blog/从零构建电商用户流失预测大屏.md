# 从零构建一个「电商用户流失预测」数据可视化大屏

> 一个全栈 + AI 的小项目：PyTorch 训练流失模型，FastAPI 做实时推理，Vue3 做科技风大屏。
> 把「数据」变成「业务方看得懂、用得上」的东西，是我做这个项目最大的收获。

---

## 为什么做这个项目？

电商平台有个经典痛点：**用户什么时候会流失？** 等运营发现某用户「很久没来了」时，往往已经晚了。

流失预测就是要解决这个「事后才知道」的问题：能不能在用户还没走之前，用他的行为特征预测出流失概率，提前干预？

于是我想做一个「能跑通完整链路」的项目：

```
数据 → 模型训练 → 在线推理 → 可视化大屏 → 运营洞察
```

一条龙，缺一不可。这不只是「调个模型」，而是**一个真正能落地的系统**。

## 第一关：数据

项目用 500 条模拟电商用户数据，18 个特征，涵盖三类信息：

- **身份**：性别、年龄段、会员等级、注册天数
- **行为**：访问页数、近 30 天活跃、距上次登录/下单天数、加购/收藏件数
- **价值**：下单次数、累计消费、客单价、退款次数

目标变量 `churn`（0=留存，1=流失），正负样本接近均衡。

做数据探索时有个很直观的发现：**流失本质是「沉默 + 低价值」**——

| 指标 | 相关性 | 含义 |
|------|--------|------|
| 下单次数 | -0.68 | 越常买越留得住 |
| 累计消费 | -0.68 | 价值越高越忠诚 |
| 距上次下单 | +0.65 | 沉默时间越长越危险 |
| 距上次登录 | +0.64 | 登录间隔是前兆 |

> 距上次下单超过 30 天的用户，流失率高达 **92%**。这个数字太直观了——**沉睡，就是流失的前奏**。

## 第二关：模型

选型上用了 **PyTorch ANN-MLP**：`18 → 64 → 32 → 1`，BatchNorm + Dropout(0.3) + Sigmoid。

训练上做了三件防过拟合的事：

1. **早停**：验证集 Loss 连续 15 轮不降就停，同时保存最优权重；
2. **Dropout + L2 正则**：双保险；
3. **分层抽样 7:2:1**：保证验证集分布稳定。

最终结果：

- 准确率 **92.16%**，AUC **0.9154**
- 流失用户召回率 **92%**——真正「会流失」的用户，抓到了九成以上

![训练/验证 Loss 曲线](../images/loss_curve.png)

> 诚实地说，模拟数据特征与标签相关性较强，指标偏乐观。但评估方法论（分层抽样、混淆矩阵、AUC、早停）是完全可迁移的。

## 第三关：推理后端

关键工程决策是**「训练 / 推理解耦」**：

```
训练模块 ──写出──► scaler.pkl / encoders.pkl / feature_cols.pkl / ann_churn.pth
                       │
FastAPI 后端 ──读取──► 只加载文件，不 import 训练代码
```

这个设计解决了经典坑：**训练和推理的预处理不一致**。把预处理对象（标准化器、编码器、特征顺序）在训练时存成 pkl，推理时直接读同一个对象，从根上杜绝「推理时重新 fit」的错误。

FastAPI 提供 8 个接口，`/api/predict` 做实时推理，`/api/dashboard` 一次性返回大屏所需全部统计。

## 第四关：数据大屏

这是最有意思的部分。需求是「科技风大数据可视化大屏」：

- 深色星空背景 + 粒子动效
- 模块发光描边、流光扫边
- 中心图形呼吸光晕
- 深蓝 + 荧光青主色调

图表层我**选了 ECharts**——大屏要「展示给业务方看」，标准专业的观感最重要。但我没有直接 `import 'echarts'` 一把梭，而是做了三层工程化：

1. **按需引入**：`echarts/core` 只注册 Pie/Bar/Line/Gauge 四种图表，构建时用 `manualChunks` 把 echarts 拆成独立 vendor 包（gzip 约 203KB），主包保持轻量；
2. **统一封装**：写了一个通用 `EChart.vue`，统一处理初始化、option 更新、`ResizeObserver` 自适应、卸载时 `dispose()`，五个图表组件都走它；
3. **科技主题**：注册了一套「tech-dark」暗色主题（深蓝 + 荧光青），五个图表风格完全统一。

而**氛围层**（星空粒子、流光边框、呼吸光晕）我用自研 CSS/Canvas——这些 ECharts 不擅长，也是最能体现前端功底的地方。图表交给你专业的，氛围交给我自己。

大屏布局：

```
┌───────────┬──────────────────┬───────────┐
│ 核心指标    │                  │ 渠道流失率  │
│ 设备占比    │  中心呼吸光晕仪表盘 │ 特征相关性  │
│ 年龄段流失率│  实时预测表单      │ 训练监控    │
├───────────┴──────────────────┴───────────┤
│ 底部：运营洞察跑马灯                      │
└──────────────────────────────────────────┘
```

![大屏整体效果](../images/dashboard.png)

**我坚持的三个可视化原则：**

1. **动效不抢数据**——流光、扫描线透明度压到极低，图表永远清晰；
2. **先选形式再上色**——流失率比较用顺序色阶条形图，设备占比用分类色环形图，相关性用红/青发散条形图；
3. **色盲安全**——分类色板做了 CVD 对比验证，正常人分不清的颜色绝不配在一起。

## 踩过的坑

1. **Vite 代理把 `/api` 前缀 rewrite 掉了** → 后端 404。后来统一让后端接口都在 `/api/*` 下，代理原样转发，一劳永逸。
2. **`torch.load` 反序列化安全警告** → 加 `weights_only=True`，顺便涨知识：pickle 反序列化可能执行任意代码。
3. **相关性图按值排序，最强的负相关信号被挤出 Top8** → 改成按绝对值排序，正负两侧的最强信号都展示。
4. **Sass `@import` 弃用警告** → 全局样式单次导入，组件直接用 CSS 变量，干净无重复。

## 总结

这个项目让我把「**模型能跑**」和「**业务能用**」之间的那层东西补上了：

- **算法层**：训练、防过拟合、评估、阈值分级；
- **工程层**：训练/推理解耦、预处理同源、安全加载、接口设计；
- **产品层**：把数据变成一屏能看的图，变成一句能行动的话。

如果继续做下去，我会：
1. 用真实数据重训，对比 XGBoost / LightGBM；
2. 加 SHAP 特征可解释性，让业务方知道「为什么」；
3. 接入时序特征，捕捉行为趋势。
